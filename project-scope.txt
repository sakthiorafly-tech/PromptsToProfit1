# PROJECT: SKILLARENA – INTERACTIVE HACKATHON PROTOTYPE

Act as a senior Product Designer, UI/UX Designer and React Frontend Developer.

I want to develop a visually impressive, highly interactive prototype of **SkillArena – Play. Prove. Get Hired.**

This is an IIT Gandhinagar hackathon prototype. I do NOT want a complete production application.

## 1. Product Vision

SkillArena is a gamified skill-development and talent-discovery platform.

Students complete real-world technical challenges, earn XP points, unlock achievements, compete on leaderboards and build a digital Skill Passport.

Colleges can use the platform to understand students' practical skill readiness. Companies can use it to discover talented candidates through practical challenges.

## 2. Strict Technology Requirements

- React JS with Vite
- JavaScript only (no TypeScript)
- Tailwind CSS
- React Router
- Lucide React icons
- Recharts where charts are useful
- Local JSON / JavaScript mock data
- LocalStorage for persisting user progress

**Do not develop:**
- Spring Boot backend
- Java backend APIs
- PostgreSQL database
- JWT authentication
- Server-side infrastructure
- Unnecessary microservices

Everything must run locally in the browser.

## 4. Gamification Logic

Implement centralized JavaScript functions for:
- XP calculation.
- Level calculation.
- Mission completion.
- Badge unlocking.
- Leaderboard updates.
- Skill progress calculation.

Rules:
- Award XP only after successful completion.
- Never award XP twice for the same mission.
- Persist progress using LocalStorage.
- Dashboard, leaderboard and Skill Passport must reflect the same data.
- Provide a Reset Demo option.

## 7. Prototype Interaction Requirements

This is NOT a collection of static HTML screens.

All major buttons must work.

The following complete flow must work:

Login ? Dashboard ? Mission Arena ? Start Mission ? Submit Answer ? Evaluate Result ? Award XP ? Unlock Badge ? Update Leaderboard ? Update Skill Passport.

Use LocalStorage so progress survives browser refresh.

Use a centralized mock data and state management approach. Avoid duplicating progress data across screens.

## 9. Development Workflow

Before coding:

1. Analyze the complete requirements.
2. Propose the application architecture.
3. Propose the screen structure and navigation.
4. Define mock data structures.
5. Define centralized gamification logic.
6. Identify any missing decisions and ask me questions if necessary.

Then develop the application incrementally.

Development priority:

Phase 1: Project setup, branding, navigation and landing page.

Phase 2: Dashboard and Mission Arena.

Phase 3: Interactive mission challenges and evaluation.

Phase 4: XP engine, levels, badges and animations.

Phase 5: Leaderboard and Skill Passport.

Phase 6: Business overview, responsive design and final testing.

After every phase, ensure the application runs successfully.

## 10. Final Acceptance Criteria

The prototype is complete only when:

- All main screens are functional.
- The complete student journey works.
- Mission evaluation works without an external API.
- XP is awarded correctly.
- Duplicate XP is prevented.
- Leaderboard updates dynamically.
- Skill Passport updates dynamically.
- LocalStorage preserves progress.
- UI is polished and responsive.
- The application can be demonstrated reliably without internet-dependent backend services.

**Most important:** Prioritize a visually impressive, functional, investor-ready prototype over production-level backend architecture.
